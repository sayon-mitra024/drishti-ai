# Model Card — Drishti AI

## Status: Real model, served externally

Inference is served by a separately deployed, private Hugging Face Space
(`sayon-mitra024/drishti-ai-inference`). This repository's Next.js app does not train,
retrain, host, or modify that model — it calls the Space's `/predict` endpoint
server-side via `@gradio/client` (see `lib/hf-inference.ts`) and adapts its two outputs
into this app's existing UI/response contract.

The model's architecture, preprocessing, and training details below are as reported by
the Space owner for this integration; they were not independently re-derived from a
checkpoint or training code in this repository (there is none here — the model lives
entirely in the separate, already-running Hugging Face Space).

| Field | Value |
|---|---|
| Architecture | EfficientNet-B0 |
| Task | Diabetic retinopathy classification, 5-class |
| Classes (exact order) | 0 = `No DR`, 1 = `Mild`, 2 = `Moderate`, 3 = `Severe`, 4 = `Proliferative DR` |
| Input size | 224×224 |
| Preprocessing | Resize to 224×224 → ToTensor → ImageNet normalization (mean `[0.485, 0.456, 0.406]`, std `[0.229, 0.224, 0.225]`) |
| Serving | Private Hugging Face Space, Gradio `/predict` endpoint, one `image` input, two outputs (prediction JSON, Grad-CAM image) |
| Explainability | Grad-CAM, generated by the model and returned as an image by the Space itself |
| Training data / evaluation metrics | Not documented in this repository — not independently verified here |
| Intended use | AI-assisted screening support for diabetic retinopathy, for use by/with clinicians |
| Non-intended use | Standalone diagnosis, treatment planning, prescribing, replacing an ophthalmologist |
| Safety | See "Medical disclaimer" in README.md — this exact wording is rendered in the app UI |

## What runs today

`POST /api/predict` calls `runHFInference()` (`lib/hf-inference.ts`), which:

1. Connects to the Hugging Face Space using `@gradio/client` and a server-only
   `HF_TOKEN` (never exposed to the browser).
2. Calls the Space's `/predict` endpoint with the uploaded image.
3. Validates the returned prediction JSON (`predicted_class`, `predicted_class_index`,
   `confidence`, `class_probabilities`) against the expected 5-class contract, rejecting
   (HTTP 502) anything malformed rather than silently passing it through.
4. Fetches the Grad-CAM image output server-side (with the same token) and re-encodes it
   as a `data:` URL before it ever reaches the browser — the client never receives a
   Hugging Face-internal temp filesystem path and never talks to Hugging Face directly.
5. Maps the result into this app's existing `PredictResponse` shape, tagging
   `model.mock: false`, `model.architecture: "EfficientNet-B0"`.

Image **quality** metrics (resolution, illumination, contrast/focus proxy) are computed
independently from the actual uploaded image via `sharp` — real, non-ML signal
processing, unrelated to the Hugging Face call.

## Local-dev-only fallback

`lib/mock-inference.ts` remains in the codebase as an explicit opt-in
(`MOCK_MODE=true`) fallback for local UI development without `HF_TOKEN` configured. It
is a deterministic, seeded heuristic — not a trained classifier — and every response
through that path is tagged `model.mock: true`. It must never be enabled in a
deployment presented as using the real model.

## Known limitations of this integration (not the model itself)

- The Space can go to sleep after inactivity; the first request after idle can take
  noticeably longer than the reported p50/p90/p99 (the app allows up to 45s before
  timing out to accommodate this).
- No retry/circuit-breaker logic beyond a single timeout per stage — a genuinely down
  Space surfaces as a clean 503/504 error rather than a retried background job.
- Training data, evaluation metrics, and dataset provenance for the model itself are
  not documented in this repository; consult the Hugging Face Space directly for those.
